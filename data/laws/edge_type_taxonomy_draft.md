# edge_type 분류 체계 초안 (v2, 검토용 — 설계 히스토리로 보존)

verb_groups.jsonl(1,127개 어근) 기준. REF/DEF/STATIVE/AMBIGUOUS 분리 후
남은 ACTION 후보(985개 그룹, 전체 출현의 49.0%) 중 상위 300개(ACTION
내 93.9%, 전체 대비 약 55%)를 대상으로 한 edge_type 분류 초안이다.

**v1(최초 초안) → v2 변경 이유**: v1은 10개 대분류에 77개 edge_type으로
너무 세분화됐다는 피드백을 받았다. v2는 두 가지 기준으로 병합했다:

1. **같은 방향·같은 법적 효과인데 표현(레지스터)만 다른 동사군은 병합.**
   예: 보고/통지/통보/알리다는 전부 "누군가에게 알린다"는 같은 방향의
   행위라 `NOTIFIES` 하나로. 세부 뉘앙스(계층 보고 의무 vs 단순 통지)가
   나중에 꼭 필요하면 edge_type을 더 쪼개기보다 **edge property**로
   얹는 걸 우선 고려한다.
2. **같은 실제 관계를 반대 문법주어로 서술한 동사쌍은 하나의 edge_type +
   고정 방향으로 정규화.** 예: "위임하다"(A가 B에게 맡김)와 "대리하다"
   (B가 A를 대신함)는 같은 관계를 다른 주어 시점에서 말한 것뿐이라
   `DELEGATES_TO`(A→B, 위임자→수임자로 방향 고정) 하나로 합친다. 이건
   4단계에서 어차피 해야 하는 능동/피동 방향 정규화와 같은 원리를 한
   단계 먼저 적용한 것.

**병합하지 않은 것**: v1→v2→v3 verb_groups 재작업에서 배운 대로,
반대 극성(APPOINTS↔DISMISSES, APPROVES↔REJECTS, ACQUIRES↔DISPOSES,
RESTRICTS↔EXEMPTS)과 실제 자금 흐름 방향이 다른 것(PAYS↔BORROWS)은
그대로 분리 유지했다. 이걸 합치면 edge label만 보고 방향(누가 누구에게)을
알 수 없게 되는, v1 verb_groups 때 지적받았던 것과 같은 문제가 재발한다.

**결과**: 77개 → **53개** (10개 대분류는 유지, 대분류당 평균 7.7개 →
5.3개).

## 0. 사전 분리 (edge_type 대상 아님, 변경 없음)

- **REF** (20그룹/29.0%): 따르다/관하다/대하다/의하다/위하다/그러하다 등 → REFERENCES류
- **DEF** (10그룹/9.4%): 같다/해당하다/간주되다/보다("~로 본다") 등 → DEFINED_AS·DEEMED_AS류
- **STATIVE** (110그룹/4.3%): 필요하다/정당하다/명백하다 등 → edge 아님, node property 후보
- **AMBIGUOUS** (2그룹/8.2%): 하다(대동사)/아니하다(부정보조) → 4단계에서 문맥으로 해소

## 6. 재산/거래/자금 (17→10)

가장 세분화가 심했던 대분류. 자금 흐름 **방향**이 실제로 다른 것들
(PAYS↔BORROWS, ACQUIRES↔DISPOSES)은 컴플라이언스 그래프에서 의미가
커서 분리 유지했고, 같은 방향의 등록형 표현만 합쳤다.

| edge_type | 대표 어근 | 병합 근거 |
|---|---|---|
| ACQUIRES | 취득, 매수, 인수, 양수 | (변경 없음, DISPOSES 반대극성) |
| DISPOSES | 처분, 매도, 매출, 양도, **이전**(병합) | 이전(방향 불명확)은 실무상 대부분 "넘겨준다"는 처분 방향으로 쓰여 통합 |
| HOLDS | 보유, 소유, **적립**(병합) | 적립(내부 유보)도 넓게 보면 "보유 상태를 유지"라 통합 |
| INVESTS | 투자, 출자 | ACQUIRES와 달리 지주회사-자회사 지분관계를 만드는 핵심 관계라 **분리 유지** |
| ISSUES | 발행, **상장**(병합) | 상장은 발행의 후속 단계 성격이 강해 통합. 상장 자체가 독립 규제 이벤트로 중요해지면 재분리 검토 |
| TRANSACTS_WITH | 거래, 매매, **체결**(병합) | 방향이 불명확한 "상대방과 거래/계약을 형성"은 하나로 |
| PAYS | 지급, 납부, 납입, **징수, 회수, 부담, 배상, 변제, 상환**(전부 병합) | 징수/회수는 지급의 반대 주어(수령자 시점)일 뿐 같은 자금 이동이라 방향 정규화(지급인→수령인)해서 통합. 배상/변제/상환도 결국 "금전을 지급"이라 통합 |
| BORROWS | 차입 | 돈이 **들어오는** 방향이라 PAYS와 반대극성 — 분리 유지 |
| GUARANTEES | 보증 | 실제 자금이동이 아니라 우발채무 관계라 분리 유지 |
| ENTRUSTS_ASSET | 예탁, 신탁 | 지주회사 자회사(신탁업 등)의 핵심 규제 대상 업무라 분리 유지 |

## 미분류 잔여 (top-300 밖, ACTION 685개 그룹)

다음 단계 승인 후 진행. 확정된 53개 edge_type에 먼저 매칭을 시도하고
남는 것만 신규 카테고리로 추가하는 순서로 처리 예정("빈도 낮다고
미분류 방치하지 않는다"는 기존 방침 유지).
